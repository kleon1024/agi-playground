# Run — the training plateau: flat stall versus surface floor, measured

**Date:** 2026-08-08
**Command:** `uv run python core/plateau_run.py`
**Hardware:** Apple M1 Pro, macOS 15.6.1, CPU-only.
**Software:** Python 3.12.9 via uv; stdlib only.
**Wall-clock:** 0.04s.
**Cost:** \$0 (local lane).

## Purpose

The optimization chapter's bowl has a real minimum with a known
condition number. A production training run stalls in a different
place: loss flattens far above where the run should end. This run
races four update rules on one flat-minimum surface L(x, y) = x^2 y^2
under a fixed 1,000-step budget, then repeats the race with an
irreducible +0.01 term, and classifies each result — so the chapter
can show which stall is an optimizer failure and which one is not.

## Reading the output

- On the flat surface, plain SGD ends 6x above the tolerance floor
  after the full budget: 6.16e-06 versus 1e-06, while momentum
  (mu=0.9), momentum (mu=0.99), and Adam all converge in budget. The
  mechanism is the step itself: each coordinate's update is
  proportional to the product of both coordinates, so near the minimum
  the step shrinks as the loss shrinks, and plain SGD's relative
  progress per step collapses toward zero — the crawl is the plateau.
- Momentum escapes the flat region by accumulating the small
  gradients; mu=0.99 escapes fastest but is still ringing at step 500
  (loss 1.30e-03) and only settles later, so the momentum knob trades
  escape speed against settling time. Adam's normalized step makes the
  escape essentially linear in budget.
- On the floored surface every optimizer stalls at 0.01 — the same
  number to four digits — so the stall is a property of the surface,
  not the optimizer. That is the diagnostic: when every update rule
  and every learning rate stalls at the same loss, the floor is in the
  data or the model capacity, not in the optimization loop.

## Notes

- Deterministic, seed-free: the surface and every update rule are
  closed-form arithmetic with no randomness, so re-running reproduces
  these exact numbers.
- "last 100" is the relative change in loss over the final 100 steps;
  "converged" means the final loss is at or below the 1e-06 tolerance.
- The saddle-point escape this chapter names (Dauphin et al., 2014,
  arXiv:1406.2572) is the high-dimensional version of the same flat
  escape problem; this run measures the flat-minimum limit case.
