# The curriculum spine: the one place chapter order lives.
#
# Chapter numbers used to be typed into each heading ("# 03 — Pretraining").
# That made every insertion an O(n) edit: adding one chapter between 03 and 04
# meant renumbering eight headings across two files each, plus any prose that
# referred to them, and nothing failed if you missed one. The table of contents
# drifted from the content silently.
#
# Now the order is this file and nothing else. Headings carry the chapter name
# only; `site/sync-docs.py` reads the position from here and composes the
# displayed title and sidebar label. Inserting a chapter is one line, and every
# chapter after it renumbers itself.
#
# One path per line, in reading order, relative to the repository root. Each
# must be a directory containing a README.md. Comments and blank lines ignored.
# `tests/test_sync_docs.py` fails if a listed path is missing, if a chapter
# directory is absent from this file, or if a heading starts carrying its own
# number again.
#
# A topic's own stages sort by their numeric prefix (`05-serve`), which is
# also their URL, so they are not listed here. A stage's *sub-chapters* have no
# prefix -- renaming `what-stops-it` to `03-what-stops-it` would change a
# published URL to buy nothing -- so an unlisted sub-chapter falls into the
# default bucket and sorts alphabetically by its sidebar label, which is not a
# reading order. List every sub-chapter of a stage that has more than one, or
# none of them; a half-listed stage sorts worse than an unlisted one.
