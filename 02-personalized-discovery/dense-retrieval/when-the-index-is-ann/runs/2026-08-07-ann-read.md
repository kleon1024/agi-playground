# Run — when the index is ANN, executed on the scan-cost model

**Date:** 2026-08-07
**Command:** `uv run python core/ann_read.py`
**Hardware:** Apple M1 Pro, macOS, CPU-only.
**Software:** Python 3.11.14 via uv; stdlib only.
**Wall-clock:** 0.03s.
**Cost:** \$0 (local lane).

## Purpose

Stage 20 retrieves by embedding. This run reads the recall-versus-scan
curve on a 100,000-item index and shows why exact search is not the
default at scale.

## Output

```
ANN vs exact, read (100,000-item index):
  scan     100: recall 0.001
  scan   1,000: recall 0.010
  scan  10,000: recall 0.100
  scan 100,000: recall 1.000

reading: exact retrieval scans the whole index — full recall,
full latency. ANN scans a fraction and accepts a recall loss at
the boundary. The index size decides which is even feasible.
```

## Notes

- Recall grows linearly with the scanned fraction: 0.1% of the index
  scanned returns 0.1% recall, full scan returns full recall.
- The index size decides feasibility: exact search is only an option
  when the whole index fits the latency budget, which is why ANN is
  the production default once the catalogue grows.
