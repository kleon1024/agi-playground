## Purpose

Stage 00's recorded runs mined two task sets; the admission rule is the
funnel's bottleneck. This run reads the recorded public model-run log and
lays out the last stage of the funnel — how many surviving tasks a blind
model call resolves — beside the recorded mining counts.

## Output

```
public task set: 2 tasks, 6 model attempts
  verdicts: {'resolved': 6}
  resolved: 6/6
  cost: $0.641 total, $0.1068 mean

recorded mining funnel (from the stage run records):
  more-itertools history: 2,423 commits; 6 candidates admitted;
  2 survived fail-at-base/pass-at-gold (0.08% of history)
```

## Notes

- The funnel's bottleneck is the admission rule, not the mining: 2,423
  commits -> 6 candidates -> 2 survivors (0.08% of history). A task set is
  defined by what it excludes.
- The 2 surviving public tasks resolve 6/6 across three blind haiku calls
  each, at \$0.107 mean — a resolvable set, which is expected for the
  contamination-prone control (more-itertools is plausibly in the model's
  training data; that is the point of the set).
- The public set is the counterpart to the private set, not another
  contamination control: it tests the same admission rule on a repository
  the model may have seen.
