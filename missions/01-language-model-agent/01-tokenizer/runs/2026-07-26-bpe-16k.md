# Run — stage 01 BPE tokenizer, 16,384 vocabulary

**Date:** 2026-07-26
**Lane:** Modal (cloud), 2 CPU cores, `debian_slim` + Python 3.12.
**Cost:** ~\$0.30 for the successful run. GPU not used; this stage is CPU-only.
**Why not the local lane:** the local machine dropped off the network mid-run.
Moving a blocked CPU job to rented CPU is what the second lane is for.

## Command

```bash
python bpe.py train /data/corpus \
    --vocab-size 16384 --docs 10000 \
    --out tokenizer.json --checkpoint tokenizer.ckpt.json
```

Corpus: `HuggingFaceFW/fineweb-edu`, `sample/10BT/000_00000.parquet` (2.15GB),
first 10,000 documents.

## Naive vs indexed

Both implementations, same corpus slice, same vocabulary target, same
tie-breaking rule:

```
naive     21.3s   1,744 merges   3.002 chars/token
indexed    0.3s   1,744 merges   3.002 chars/token
identical merge lists: True
```

**71× speedup, byte-identical output.** At the naive rate the full 16k run was
measured mid-flight at ~2.4 s/merge, projecting to roughly ten hours; the
indexed run finished in 8.8 minutes.

## What went wrong, and what it cost

Recorded because the failures were more instructive than the success:

1. **A 1h15m local run was lost** when the machine left the network. It would
   never have finished anyway — it was the naive implementation, so it was
   roughly 10% of the way through a ten-hour job.
2. **The run was invisible.** Python block-buffers stdout when redirected, so a
   75-minute job wrote nothing to its log. `flush=True` on progress output is
   now in the code with a comment explaining why.
3. **A healthy process was nearly killed as hung.** `pgrep -f 'bpe.py train' |
   head -1` matched the wrapper shell, reporting 0% CPU and 1.8MB RSS. The real
   process was at 100%.
4. **The first Modal launch was cancelled by its own client.** `modal run
   --detach` was wrapped in `timeout 180`; killing the client propagated a
   cancellation. `--detach` survives the client *exiting*, not being
   *terminated*.
5. **The original time estimate was wrong by 5×.** Extrapolated from a
   2,000-document run without accounting for unique-word growth. The correct
   response was to fix the algorithm, not to wait longer.

Training is now resumable — merges checkpoint every 500 — so a repeat of (1)
costs minutes rather than hours. Resume was verified by training to 1,200 vocab
uninterrupted, then again with a stop and resume at 1,000, and comparing:
944 merges, bit-identical.
