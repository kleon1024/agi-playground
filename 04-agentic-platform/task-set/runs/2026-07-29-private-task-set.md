# Mining the private task set from this repository's history

First construction of the contamination-control task set. The question this run
answers is not "how many tasks can we get" but "how many of the tasks we get
are real", and the answer — 2 of 4 candidates, from 100 commits — is the
finding.

## Command

```bash
cd 04-agentic-platform/00-task-set/core
uv run python mine_history.py candidates
uv run python mine_history.py mine            # -> tasks/candidates.jsonl
uv run python mine_history.py verify --write  # -> tasks/private.jsonl
```

The two output paths were one path when this run was first recorded. Re-running
`mine` to measure the wall-clock below overwrote the verified manifest with the
unverified candidate set, and that is what got committed in `650c7ad`; the
correction and the reason the filenames now differ are in the chapter.

## What the verifier rejected, and why that matters more

Two candidates were rejected for **the target tests already passing at the base
state**. Both are `tests/test_sync_docs.py` additions, and both contain this:

```python
index = ROOT / "site" / "docs" / "platform" / "index.md"
if not index.is_file():
    return  # site not synced in this environment
```

`site/docs/` is generated by `npm run sync` and is gitignored, so in a fresh
worktree the file does not exist, the function returns, and **pytest records a
pass**. The test is not skipped and nothing in the output says it declined to
run. It reports success for a page it never read.

That is the same defect class this mission was built around, found in this
repository's own test suite by the check that mines it. A guard that reports
success when its subject is absent is indistinguishable from a guard that
passed, and the only reason it surfaced here is that a task-mining rule —
*the test must fail before the fix* — refuses to accept a test that never fails.
The mission's guardrail on the agent is the same rule pointed at the agent
instead of at us.

These two are excluded from the task set rather than repaired, and the defect
is recorded here as a repository issue, not silently fixed to raise the yield.

## The bug in the verifier itself

The first run of this verifier reported **1 of 4**, wrongly rejecting
`private-b81c414` — the best task in the set — with "target tests still fail
after gold patch". The cause:

```python
return proc.returncode == 0        # wrong
```

pytest's exit code is not a boolean. `tests/test_decode_correctness.py` opens
with `pytest.importorskip("torch")`, so under the default environment nothing is
collected and pytest exits **5**, which means *no tests ran*. Treated as a
boolean that reads as "failed", which is exactly backwards: it makes an
unrunnable test look like a valid task at base, and then look unfixable after
the gold patch.

The three outcomes are now distinguished (`PYTEST_PASSED` 0, `PYTEST_FAILED` 1,
`PYTEST_NOTHING_COLLECTED` 5), and exit 5 disqualifies a task instead of scoring
it. The miner also now resolves the test command per task by trying candidate
dependency groups and keeping whichever one actually collects the tests, which
is why `private-b81c414` carries `uv run --group torch pytest -q ...` in the
manifest rather than the default command.

Both of these — the collapsed exit code and the early-returning test — are the
same failure: a check that cannot distinguish "passed" from "did not run".

## What this run does not establish

Nothing about agent performance; no agent has been run. Nothing about task
difficulty beyond the fact that each task's test fails at base and passes with
the author's own patch — a patch written by someone who had already diagnosed
the bug. N = 2 is a contamination control and cannot support a significance
claim of any kind; per [`../../mission.yaml`](../../mission.yaml) it is reported
separately from the public set and never pooled with it.

The mining rule also selects for a narrow kind of bug: one whose author wrote a
test in the same commit. Fixes committed without a test, fixes whose test came
later, and fixes to non-Python code are all invisible to it, and that is most of
the 15 `fix` commits in this history.
