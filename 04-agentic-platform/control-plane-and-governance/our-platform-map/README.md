# The whole topic, drawn as the platform it builds

**Question:** nineteen stages and six groups can read as a list. This
chapter draws them as what they actually are — the planes of one platform,
each owning a decision and handing its artifact to the next. Where does
every verified run sit on that map?

**The artifact this chapter follows** is the diagram: call → intent →
harness → capabilities → organization → production, with each plane's
artifact crossing to the next.

## What the map makes visible

Two properties the list hides. **The artifact is the contract** — the map
only works if each plane hands a concrete thing (task, plan, patch, agent,
decision, outcome) to the next, which is the same rule the mission's
evidence contract applies to a single patch. **The verified runs sit on
their own plane** — every number in this topic belongs to the plane that
owns its evidence, and the frontier claims (surveys) sit beside them as
dated reference, never as measurements.

## What this does not say

It does not claim the map is the industry's canonical architecture — the
TokenJam nine-layer and NVIDIA seven-plane maps are different cuts of the
same reality (the-platform-layers chapter compares them). It claims this
topic's stages are one coherent platform, and the diagram is the proof
that the reading order is a build order.
